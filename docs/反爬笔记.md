# 反爬笔记

2026-11 一个下午加一个晚上，把几个主流的以图搜图站和 pixiv 全撞了一遍。下面每条都是实测出来的，不是查文档抄的。失败的尝试也留着——省得你再撞一次。

环境：Windows，本地代理 `127.0.0.1:7897`，Python 3.13，`requests 2.34`、`curl_cffi`。

---

## 0. 先解决网络

这台机器上直连这些站会被重置：

```
ConnectionError: ('Connection aborted.', ConnectionResetError(10054, '远程主机强迫关闭了一个现有的连接。'))
```

DNS 能解析，TCP 也被 RST。必须走代理。

**坑一**：`requests` 默认会读系统代理（Windows 是注册表里的 `ProxyServer`），但对着这个本地代理会报：

```
ProxyError: Unable to connect to proxy
SSLError: EOF occurred in violation of protocol (_ssl.c:997)
```

**坑二**：`session.trust_env = False` 也不够——它只是不读环境变量，系统代理还在。

**能用的写法**：显式传 `proxies`，两个键都要给：

```python
PROXIES = {"http": "http://127.0.0.1:7897", "https": "http://127.0.0.1:7897"}
session.trust_env = False
r = session.post(url, proxies=PROXIES, ...)
```

`curl_cffi` 也一样，显式传 `proxies=`，不要靠环境变量。

## 1. SauceNAO：不用注册

**最开始的错误结论**：以为要 API key，去 `saucenao.com/user.php?page=register` 注册。

**注册页打不开**，返回 403：

```
HTTP 403  |  Just a moment... *{box-sizing:border-box;...}
```

Cloudflare 的 JS 挑战页。这不代表它关了，只是拦爬虫。

**真相分两种调用**：

| 调用方式 | 结果 |
|---|---|
| JSON API，不带 key | `{"header":{"status":-1,"message":"The anonymous account type does not permit API usage."}}` |
| JSON API，带 key | 正常 |
| **网页表单 POST，不带 key** | **HTTP 200，21746 字节 HTML，有完整结果** |

所以匿名网页查询是通的，API 才要 key。

**正确的调用**：

```python
from curl_cffi import requests as creq, CurlMime

mp = CurlMime()
mp.addpart(name="file", data=img_bytes, filename="x.jpg", content_type="image/jpeg")
r = creq.post("https://saucenao.com/search.php",
              multipart=mp,
              data={"db": "999", "numres": "8"},
              headers={"User-Agent": UA, "Referer": "https://saucenao.com/"},
              proxies=PROXIES, impersonate="chrome124", timeout=70)
mp.close()
```

`Referer` 建议带上。`db=999` 是全部数据库。

**解析**：

```python
soup = BeautifulSoup(r.text, "html.parser")
for blk in soup.select(".result"):
    title = blk.select_one(".resulttitle").get_text(" ", strip=True)
    cols  = [c.get_text(" ", strip=True) for c in blk.select(".resultcontentcolumn")]
    urls  = [a["href"] for a in blk.select("a")
             if a.get("href","").startswith("http") and "saucenao.com" not in a["href"]]
```

第一个 `.result` 通常是你自己上传的预览图，没有外部链接，跳过。

**坑三：相似度阈值**。60% 以下全是噪音。实测一张图返回的最高命中 49.45%，指向一个「同名但完全不同」的作品：

```
1.  49.45%  pixiv  薔薇園のヴァンパイア   pixiv ID: 102921819  Member: hrathnir
```

长得像不等于同一张。**60% 以下直接丢**。

**坑四：源站会抽风**。同一个查询，隔几分钟：

- 第一次 `HTTP 502`
- 第二次 `HTTP 521`（Web Server Is Down）
- 第三次 200，正常

加个 3 次重试，间隔递增，就没事了。

## 2. pixiv：CF 只守页面，不守接口

这是整个下午最有用的一个发现。

| URL | 结果 |
|---|---|
| `https://www.pixiv.net/artworks/127381096` | **403**，5916 字节的 `Just a moment...` |
| `https://www.pixiv.net/ajax/illust/127381096` | **200**，39839 字节 JSON |
| `https://www.pixiv.net/touch/ajax/illust/details?illust_id=127381096` | **200**，13488 字节 JSON |

**换 TLS 指纹没用**。`chrome124` / `chrome120` / `safari17_0` / `firefox133` 四种全试，HTML 页面一律 403，两个 ajax 接口一律 200。说明 ajax 接口根本没挂 CF 挑战，不是指纹问题。

**调用**：

```python
hdr = {
    "User-Agent": "Mozilla/5.0 (...) Chrome/131.0.0.0 Safari/537.36",
    "Referer": "https://www.pixiv.net/",
    "Accept": "application/json",
    "Accept-Language": "ja,en-US;q=0.9",
}
r = creq.get(f"https://www.pixiv.net/ajax/illust/{pid}",
             headers=hdr, proxies=PROXIES, impersonate="chrome124")
b = r.json()["body"]
```

**能拿到的字段**：

```
illustId, illustTitle, illustComment, userId, userName, uploadDate,
width, height, pageCount, illustType (0=illust 1=manga 2=ugoira),
xRestrict (0=全年龄), viewCount, bookmarkCount,
tags.tags[].tag, urls.{mini,thumb,small,regular,original}
```

**一个限制**：未登录时 `urls.original` 返回 `None`。不是解析错了，是 pixiv 不给未登录用户原图直链，只给 `regular`（master1200）。要原图得带 `PHPSESSID`。

## 3. ascii2d：过不去

日系图最强的检索站，两个通道（`search[color]` 色合检索、`search[texture]` 特征检索）。

**全试过了，一律 403**：

| 尝试 | 结果 |
|---|---|
| `requests` POST，带完整浏览器头 | 403 |
| `curl_cffi` + `impersonate="chrome124"` | 403 |
| 换成 `chrome120` / `safari17_0` / `firefox133` | 403 |
| 加 `Referer` | 403 |

**为什么过不去**：它要的不是 TLS 指纹，是**浏览器真的把 JS 挑战跑完**再拿 `cf_clearance` cookie。TLS 指纹伪装解决的是「看起来像浏览器」，解决不了「证明你跑过 JS」。

真要过，得上无头浏览器（Playwright / DrissionPage）跑一次挑战拿 cookie，再带着用。成本比它能给的信息高，放弃了。

## 4. iqdb：能通，但慢且库老

```bash
POST https://iqdb.org/
form: file=<jpeg>, service=1
```

**能通**，但一次查询 **40–122 秒**（`requests` 版 122 秒，`curl_cffi` 版 40 秒超时）。timeout 要给到 120 以上。

**库很老**：只收 danbooru / konachan 系，pixiv 原创图基本没有。实测那张 pixiv 图查完 0 条。

**适用场景**：找老番同人、找壁纸源。新图别指望。

---

## 5. Yandex 图搜：接口参数没调通

`https://yandex.com/images-apphost/image-download` 是最常用的免 key 上传接口，但一直：

```
HTTP 400  Incorrect avatar size
```

`images_avatars_size` 这个参数试过 `preview`、去掉、换 `rpt=imageview`，全都是同一个错。参数值没试对，放弃了。

（如果你调通了，欢迎 PR。）

## 6. 汇总：现在什么能用

| 引擎 | 状态 | 强项 | 弱项 |
|---|---|---|---|
| SauceNAO（匿名） | ✅ 免 key | pixiv / twitter / danbooru 全覆盖 | 60% 以下噪音，源站偶发 5xx |
| pixiv ajax | ✅ 免 key | 元数据全字段 | 原图要登录 |
| iqdb | ✅ 免 key | 老番、壁纸 | 慢、库老 |
| ascii2d | ❌ CF 403 | — | 要过 JS 挑战 |
| Yandex | ❌ 参数未通 | — | — |

**顺序建议**：SauceNAO → 拿到 pixiv ID → 调 ajax 补全。两个请求解决 90% 的问题。

## 7. 杂项

**`curl_cffi` 新版不支持 `files=`**：

```
NotImplementedError: files is not supported, use `multipart`.
```

要这样：

```python
from curl_cffi import CurlMime
mp = CurlMime()
mp.addpart(name="file", data=img_bytes, filename="x.jpg", content_type="image/jpeg")
r = creq.post(url, multipart=mp, ...)
mp.close()
```

注意参数名是 **`data=`** 不是 `content=`。

**PowerShell 里跑 Python 的中文输出**：

```powershell
$env:PYTHONIOENCODING="utf-8"
python -X utf8 script.py
```

**PowerShell 的 `&&` 在旧版本不存在**，用 `;` 分开。

**用 PowerShell 写文件会带 BOM**，Python 读要 `encoding="utf-8-sig"`，或者写完用 Python 重新落一遍不带 BOM。

**`ffmpeg` 的 hstack 在 PowerShell 里会被吃掉**：`[$i:v]` 里的 `$i` 被当变量展开成空。用 Pillow 拼图，或者把 filter 写进文件再 `-filter_complex_script`。
